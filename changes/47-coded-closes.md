# 47 — coded closes

**What changed for a user:** the floor's "Maintenance Code" box at close is now backed by one `failure_code` list that the plant owns: every plant gets the 19 live codes with their descriptions the first time it loads (no migration, no re-seed, so live Cosmos gets them too), the maintenance head edits them — switching a code off instead of deleting it, and adding Bhavin's old codes as aliases (`ele`, `hyd`, `rot` ride on E, HY, RT) — on a generated Settings → Lists screen the list is created when that screen or the first coded close is reached — never by a write on the config read — and a live breakdown close with no code is refused by the server with a 422 naming `report.failureComponent` while a code that was switched off still shows on the old reports that used it (the form lists the plant's maintenance codes, the same 19 values, until the failure list exists, so the floor is never blocked in the deploy window); on the way in and in every figure, an old code resolves through its alias (and `ELE`/`ele` from a queued phone) to its one entry, so a legacy `ELE` row and a new `E` close count as one code in the annual "By cause" table and the breakdown log, and the old report still shows the code it recorded. The plan is `docs/slices/47-coded-closes.md`: packet 47a is the list and its tenant default with the alias contract, 47b is the coded close/read and the one-code count in the loader (the four columns are in place from 46; only the component is required here, the other three wait for M6's suggestion), and 47c is the screen, the floor's picker and the browser journey; no migration, no new table, no dependency.
