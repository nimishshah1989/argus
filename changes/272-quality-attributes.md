- A pull request must now satisfy fifteen numbered quality attributes, and `pnpm quality` (locally) and `pnpm quality:pr` (in CI) check the ones a machine can decide; the rest are returned by the fresh reviewer as a Q table. A failing attribute blocks the merge; a waiver is a ledger ruling, never a silent exception.
- `pnpm push:check` now refuses to push a HEAD with no commits ahead of `origin/main`, or a tree with unresolved rebase conflicts (the 17 Nov incident), so a rebase left mid-conflict cannot empty the PR.
- Q15 "Merge keeps main green": after each merge the queue checks out the new `main` and runs the test files the merged PR touched, hotfixing a red tree before the next merge — on 17 Nov a stale expectation from #206 met #258's new criticality default and left `main` red, blocking every PR until the next PR's CI found it.
