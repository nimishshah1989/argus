# Glossary

_Domain terms, one line each. Agents use these words exactly in code, tickets and UI. Maintained by `domain-modeling` during Plan._
_Exact time definitions (downtime, repair, response, hands-on) live in `docs/spec/DOMAIN.md` §5; Gujarati words in `docs/design/gujarati-glossary.md`._

| Term                   | Means                                                                                                                                                                                                | Not to be confused with                        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Uptimo                 | The product's name in code and package names (`@uptimo/*`)                                                                                                                                           | Argus (the repo's name), Cosmos (the customer) |
| Cosmos                 | Cosmos Engitech, the one plant (tenant) on Uptimo today, about 192 machines                                                                                                                          | a tenant in general                            |
| Tenant                 | One company's sealed slice of the data; every table carries `tenant_id` under row-level security                                                                                                     | a plant user or login                          |
| Bhavin                 | Author of the incumbent v3 ticket app and analytics workbooks that Uptimo replaces; his figures are the reference                                                                                    | a user role                                    |
| Ticket                 | One breakdown (BD-nnnn) or work request (WR-nnnn); kinds: stopped, support, general                                                                                                                  | a GitHub issue                                 |
| Breakdown              | A ticket where a machine stopped or is struggling                                                                                                                                                    | PM                                             |
| Ticket event           | One append-only line per action on a ticket; a ticket's times and figures are computed from these                                                                                                    | audit log                                      |
| Running again          | The machine is back while the ticket stays open; stops the downtime clock                                                                                                                            | closed                                         |
| Handback (sign-off)    | Production confirms or disputes a fix; it can time out                                                                                                                                               | close                                          |
| Two clocks             | Acknowledge (report → acknowledge or start) and restore (report → close or running again)                                                                                                            | SLA policy                                     |
| SLA policy             | Minutes allowed per severity for the two clocks                                                                                                                                                      | escalation rule                                |
| Severity (S1–S4)       | How urgent a ticket is, looked up from machine criticality (A/B/C) and its state                                                                                                                     | priority group in the Action Center            |
| Escalation (ladder)    | Who is told (L1–L4 or vendor) when a clock is missed                                                                                                                                                 | roster                                         |
| Roster                 | Who is on duty at which ladder level, by date and shift                                                                                                                                              | escalation rule                                |
| Shift                  | The plant's working periods; the production date is the date the shift started                                                                                                                       | calendar day                                   |
| Segment / group / cell | The machine hierarchy; a cell is a floor area, and a machine's cell moves are dated                                                                                                                  | category (machine type)                        |
| Crew / work segment    | The people on a job, and each person's stretches of hands-on time                                                                                                                                    | segment (machine hierarchy)                    |
| Coded close            | Failure codes on the breakdown report: component, mode, cause, action                                                                                                                                | free-text remarks                              |
| Breakdown report       | The closing record of a breakdown, with codes, people and a PDF                                                                                                                                      | Breakdown Log (the screen)                     |
| PM                     | Preventive maintenance: plans raise PM tickets on a schedule; each has a PM report                                                                                                                   | breakdown                                      |
| MTTR                   | Mean time to repair: maintenance time ÷ repairs                                                                                                                                                      | response time                                  |
| MTBF                   | Mean time between failures: operating time ÷ failures                                                                                                                                                | uptime                                         |
| Availability           | MTBF ÷ (MTBF + MTTR)                                                                                                                                                                                 | OEE                                            |
| BD % / PM %            | Breakdown and PM shares of maintenance hours, by month and cell (Bhavin's A1)                                                                                                                        | breakdown count                                |
| A1 … A10               | Bhavin’s numbering of his analytics views; code and URL ids only, never shown                                                                                                                        | ticket numbers                                 |
| Why-Why                | The root-cause form for a breakdown (A6), with Start, Save and PDF                                                                                                                                   | Problem Analysis (A10)                         |
| Engine                 | The code that computes every figure from tickets and stores them as snapshots by run, period and subject                                                                                             | the server as a whole                          |
| Answer key             | Bhavin's figures frozen at a date (`fixtures/answer-key/`); the engine must reproduce them exactly                                                                                                   | test fixtures in general                       |
| Parity                 | Uptimo keeps the intent of every "Keep" row of Bhavin's tools (`docs/spec/parity.yaml`)                                                                                                              | pixel likeness                                 |
| Legacy mode            | Engine rules that reproduce Bhavin's arithmetic, quirks included                                                                                                                                     | v1 screens                                     |
| Forecast freeze        | The monthly forecast is frozen on the 1st and later scored against what happened                                                                                                                     | engine run                                     |
| Hot                    | The highest band in the frozen monthly forecast                                                                                                                                                      | S1 severity                                    |
| Action Center          | The prioritised list of decisions and nudges to act on, acknowledge or snooze                                                                                                                        | Dashboard                                      |
| Nudge                  | One engine-raised prompt in the Action Center                                                                                                                                                        | notification (push)                            |
| Asset register         | AMC, warranty, legal and calibration records in one table, with reminders                                                                                                                            | machine register (the list of machines)        |
| Utility loss           | A plant-wide power or air failure, stored as a general ticket                                                                                                                                        | a breakdown                                    |
| Floor (floor phone)    | The operators' shared low-end Android phone face, in Gujarati (`/floor`)                                                                                                                             | Desk                                           |
| Desk                   | The technicians' and supervisors' face, in English (`/desk`)                                                                                                                                         | Floor                                          |
| Board (TV board)       | The read-only wall TV (`/desk/board?kiosk=1`), always dark, never shows money                                                                                                                        | Dashboard                                      |
| Acting person          | Who is using a shared login right now; recorded on every action                                                                                                                                      | login                                          |
| Money rule             | Rupee figures are shown only to roles allowed to see money (`packages/domain/src/permissions/views.ts`)                                                                                              | —                                              |
| v1 / v2 screen         | v1 is the first frontend; v2 is the redesign in Bhavin-matched language. A v2 screen ships live and deletes its v1                                                                                   | v1 of the product (the release)                |
| Coverage table         | Per v2 screen: every v1 and spec item and where it lives in v2; a MISSING row blocks the screen (`docs/design/v2/COVERAGE.md`)                                                                       | test coverage                                  |
| Gallery                | `/gallery`: v2 screens rendered from the frozen answer-key fixtures, no server needed; staging and dev only                                                                                          | the live screens                               |
| Kit                    | The shared v2 UI parts in `apps/web/src/ui/v2/` (shell, data table, KPI card, entity chip, drawer, chart card)                                                                                       | the loop's global design kit                   |
| Entity chip            | How a machine, cell, person or decision is always shown: a chip that opens its drawer                                                                                                                | a plain link                                   |
| Status                 | How a figure is doing against its yardstick or target: good, watch, bad, or neutral when there is none                                                                                               | tone (what kind of figure it is: loss, gain)   |
| Period                 | The one span of dates every figure on a page counts over, stated on the page (this year, or history and live)                                                                                        | as-of date (where the period ends)             |
| Young machine          | A machine under 300 days from its purchase date; the OEM screen's subject (ADR 0051)                                                                                                                 | a machine inside warranty                      |
| OEM cause              | Who a young machine's breakdown is put down to: OEM / build defect, Installation / commissioning, Our side, or Not decided; only a person picks it, stored as an `oem_cause` ticket event (ADR 0051) | the problem group (Problem Analysis)           |
