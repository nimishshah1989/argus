# 0003 — Auth

Date: 10 November 2026
Status: accepted — decided by the M0 auth spike

## Decision

**Hand-rolled sessions.** No better-auth, no Auth.js, no external identity provider.

- `login`: username unique per tenant, Argon2id password hash, role, shared flag, optional person, optional cell, disabled.
- `session`: opaque random token stored only as SHA-256, login id, device label, `last_seen_at`, `expires_at`, `revoked_at`, optional `acting_person_id`.
- 30-day sliding session; logout revokes it; change password revokes the others; device list and revoke in M2.
- Tenant resolved from the host; session lookup goes through one narrow `app_router` function that returns the tenant before `app.tenant_id` is set.
- Shared login: no person on the login; the acting person is chosen from the plant’s active people and written on every action. Never free text.
- Login and password endpoints are rate-limited; errors are generic; no user enumeration.

## Spike evidence

Run on 10 November 2026: Postgres 16.15 in Docker, Node 24.14, better-auth 1.7.19, `@node-rs/argon2` 2.2.2. The throwaway scripts were deleted; the full report is `docs/plan/spikes/auth.md`.

| Check                        | Hand-rolled                                                               | better-auth 1.7.19                                                                  |
| ---------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Schema                       | `login` + `session`, exactly `DOMAIN.md`                                  | `user` + `session` + `account` + `verification`; organization plugin adds 3 more    |
| Tenant on the session        | `session.tenant_id`, RLS policy                                           | `session.tenantId` accepted but **null on sign-in**; needs a custom hook or a join  |
| RLS                          | 1 row per tenant, 0 cross-reads, `app_router` lookup returns the tenant   | not tested end-to-end; session table is not tenant-scoped                           |
| Shared phone / acting person | first-class (`shared`, `acting_person_id`)                                | not modelled; custom fields and per-action logic                                    |
| Password hash                | Argon2id                                                                  | scrypt by default; custom Argon2id works                                            |
| Session length               | 30 days, sliding                                                          | 30 days configurable; default 7                                                     |
| Bearer token                 | opaque 32-byte token, SHA-256 at rest                                     | bearer plugin returns a token; session table stores `token`                         |
| Username / email             | username only; no email needed                                            | email required; username plugin adds username                                       |
| Code                         | 132 lines including SQL schema and a two-tenant test (~70 lines of logic) | 33 lines of config with a memory adapter; RLS/shared-phone integration not included |
| Dependencies                 | `pg`, `@node-rs/argon2`                                                   | better-auth plus its transitive tree                                                |

better-auth is a good library. It is simply a worse fit for this model: email-first, four core tables, no tenant on the session, no shared-phone/acting-person concept, and an API that moves between minors. At 15–250 users, the security we need comes from a small, tested, single auth path and a human review, not from a larger library.

## Consequences

- We own the security of the auth path. Mitigations: one mechanism for every client; Argon2id with tuned parameters; a 32-byte random token stored only as SHA-256; constant-time password verification; rate limits; revoke; no token in URLs or logs; a session lookup function with the narrowest possible grant; tests for replay, expiry, revoke, shared phone and cross-tenant lookup; a human security review before cutover.
- `DOMAIN.md` is already correct; no schema rewrite is needed.
- `better-auth` is removed from `SPEC.md`, `BUILD-PROTOCOL.md` and `THIRD_PARTY.md`.
- The production implementation and tests are M0-0.4; the spike code is not shipped.

## Rejected

- **better-auth as the auth layer** — schema/RLS/shared-phone mismatch, email requirement, session tenant gap, extra dependency and version churn; not worth a custom hook layer for this model.
- **Auth.js, Lucia, Auth0, Clerk** — wrong shape, deprecated, or per-user cost.
- **Two auth systems** — the one thing that guarantees a security bug.
