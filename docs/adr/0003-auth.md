# 0003 — Auth

Date: 10 November 2026
Status: proposed; final after the M0 auth spike

## Context

The auth model is unusual:

- Personal logins and **shared phones** (a login with no person, where every action records the acting person).
- Tenant resolved from the **host name**, before login.
- A 30-day sliding session, a device list and revoke.
- Row-level security: the session lookup must find a tenant before `app.tenant_id` can be set, so it goes through a narrow `app_router` function.
- About 15 users at Cosmos, growing to a few hundred; no social login, no email-first flow.

`SPEC.md` names better-auth with the username, admin, organization, multi-session and bearer plugins. `DOMAIN.md` defines its own `login` (Argon2id) and `session` (token hash) tables. They cannot both be the schema.

## Decision (proposed)

**Default: hand-rolled sessions**, unless the M0 spike shows better-auth can express the model without a second schema.

- `login`: username unique per tenant, Argon2id password hash, role, shared flag, optional person, optional cell, disabled.
- `session`: opaque random token stored only as SHA-256, login id, device label, `last_seen_at`, `expires_at`, `revoked_at`; 30-day sliding.
- Login: verify password, create a session, return the token and user; any request hashes the token, looks it up through `app_router`, sets the tenant.
- Shared login: the acting person is chosen from the plant’s active people and written on every action as `acting_person_id`; never free text.
- Logout revokes the session; change password revokes the other sessions; device list and revoke in M2.
- Rate limit login and password endpoints; generic error messages; no user enumeration.

## Spike

Time-boxed to one day in M0:

1. Build the hand-rolled flow against a local Postgres with RLS and the session lookup function.
2. Build the same flow with better-auth (username + admin + multi-session + bearer, custom Argon2id hasher) and record what it cannot express.
3. Choose, write the result here, and delete the losing spike.

## Rejected

- **better-auth as the only model without a spike** — its email-first `user`/`session`/`account` schema, scrypt default and organization tables may not fit shared phones and tenant-from-host; the cost of finding out mid-M1 is high.
- **Auth.js / Lucia / Auth0 / Clerk** — wrong shape, deprecated, or per-user cost.
- **Two auth systems** — the one thing that guarantees a security bug.

## Consequences

- If hand-rolled wins, `DOMAIN.md` is already correct; better-auth is removed from the spec and `THIRD_PARTY.md`.
- If better-auth wins, `DOMAIN.md` is rewritten to its tables and the shared-phone/acting-person fields are added; the hand-rolled tables are not created.
- Either way, the security review before cutover checks token storage, revoke, rate limits and the `app_router` function.
