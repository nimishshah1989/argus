# Coverage: Breakdown Log (v2, `screens/v2/breakdown-log/`)

Built from `screens/analytics/BreakdownLog.tsx`, `log-values.ts`, `BreakdownsPage.tsx`, `e2e/analytics-log-paging.spec.ts`,
`e2e/analytics-breakdowns.spec.ts` (the log test) and the engine figure `breakdown-log` (`packages/domain/src/analytics/breakdown-log.ts`).
Test data is the engine's own output for the 11 November plant (1,343 rows), held equal to the gallery stand-in by `engine-equal.test.ts`.

**Why not the tickets route.** The only cursor-paged route is `GET /tickets`. Its reply carries no Sr No, shift, maintenance code or
done-by names and has no sort, search or count, so it cannot serve this log without losing five columns and every filter. The screen
therefore asks for pages in the shape a paged log endpoint would answer (`cutPage`, `serve.ts`) and today cuts them from the engine's
printed log; the one swap is the provider. Ledger: "Breakdown Log pages in memory until 75b / a paged log endpoint".
