# Coverage: Breakdown Log (v2, `screens/v2/breakdown-log/`)

Built from `screens/analytics/BreakdownLog.tsx`, `log-values.ts`, `BreakdownsPage.tsx`, `e2e/analytics-log-paging.spec.ts`,
`e2e/analytics-breakdowns.spec.ts` (the log test) and the engine figure `breakdown-log` (`packages/domain/src/analytics/breakdown-log.ts`).
Test data is the engine's own output for the 11 November plant (1,343 rows), held equal to the gallery stand-in by `engine-equal.test.ts`.

**Live (ticket 91).** The screen is at `/analytics/breakdowns` (v1's address; no `?screen=`, an unknown one and `?screen=breakdown-log` all open it) on the
engine's `breakdown-log` figure from `GET /analytics/figures`, the reply v1 read, through `Page.tsx` and the seam. The figures refresh every 30 seconds as in v1
(`useRefreshOnFigures`); the page on screen stays while the next loads, for the login it was read for only (`useKept`). v1's page (`BreakdownLog.tsx`,
`log-values.ts`, their unit tests, the group page's log branch) is deleted in the same PR; their assertions live on in `page-shape.test.ts`,
`day-order.test.ts`, `page-content.test.ts` (filters) and the real-server specs `analytics-breakdowns.spec.ts` and `analytics-log-paging.spec.ts`.

**Why not the tickets route.** The only cursor-paged route is `GET /tickets`. Its reply carries no Sr No, shift, maintenance code or
done-by names and has no sort, search or count, so it cannot serve this log without losing five columns and every filter. The screen
therefore asks for pages in the shape a paged log endpoint would answer (`cutPage`, `serve.ts`) and today cuts them from the engine's
printed log; the one swap is the provider. Ledger: "Breakdown Log pages in memory until 75b / a paged log endpoint".

## Fidelity pass against Bhavin's platform (21-Nov-2026)

Bhavin's code is `docs/discovery/real-2026-11-13/cosmos_platform-2026-11-11.html` (B11), `renderBreakdowns` and `openBdView`. The engine's
`breakdown-log` figure now also sends `extra` beside the key's own page (which is unchanged, so the answer-key table is untouched): `extra.rows` pairs with
the table's rows one for one (who supported the job, its type E, M or E/M, how long a stop it was) and `extra.codes` is the plant's code list with descriptions. A saved reply from before
this carries neither and the log still opens, with no Supported By and no code meaning.
