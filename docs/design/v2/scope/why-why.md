# Coverage: Why-Why (v2, `screens/v2/why-why/`)

Built from `screens/analytics/WhyWhyPage.tsx`, `why-why-parts.tsx`, `e2e/analytics-whywhy.spec.ts` and the engine figure `a6-why-why` (`a6-why-why.ts`). Test data is the frozen answer `fixtures/answer-key/a6-why-why.json`.

**Finding in v1.** v1 pairs row N of the candidate table with `figure.drill.ids[N]`. The engine sorts every figure's drill ids (`engine.ts drillOf`, `.sort()`), while the rows are worst first, so on a plant with two or more candidates Start Why-Why can open and save a record on a different ticket. v1's e2e stubs one row and never sees it. v2 does not copy it: no Start or View is shown until each row carries its own ticket id.
