# Coverage: Why-Why (v2, `screens/v2/why-why/`)

Built from `screens/analytics/WhyWhyPage.tsx`, `why-why-parts.tsx` (both deleted in the PR that made this screen live), `e2e/analytics-whywhy.spec.ts` and the engine figure `a6-why-why` (`a6-why-why.ts`). Unit-test data is the frozen answer `fixtures/answer-key/a6-why-why.json`. **Live at v1's address** (`/analytics/breakdowns?screen=a6-why-why`) on `GET /analytics/figures` and the same Why-Why routes (`GET` and `PUT /tickets/:id/why-why`, the PDF).

**A row acts on its own ticket.** The engine sorts every figure's drill ids, so a row is never tied to a ticket by its place in them (the defect fixed in #515). The engine prints the ticket beside each row (`rowTicketIds`, in row order); v2 reads that, sends it to the server and never prints it. A row the engine named no ticket for offers no action, so nothing is ever saved on a guessed ticket.
