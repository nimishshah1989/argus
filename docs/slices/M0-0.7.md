# M0-0.7 — Infrastructure

## Goal

One command builds a runnable server image; one command deploys and rolls back; Terraform provisions RDS, S3, IAM, Secrets Manager, EC2 and the billing alarm in ap-south-1. The restore drill is written and executed when the AWS account exists.

## Files

- `scripts/build-server.ts` — bundle `apps/server` to a single ESM file with esbuild.
- `infra/server.Dockerfile` — Node 24 image that installs, builds and runs the bundle.
- `infra/docker-compose.yml`, `infra/Caddyfile` — Caddy + server.
- `infra/deploy.sh` — `staging | production | rollback <tag>`.
- `infra/terraform/main.tf`, `terraform.tfvars.example`, `README.md` — VPC, EC2, RDS, S3, IAM/OIDC, Secrets Manager, Budgets.
- `infra/RESTORE.md` — restore runbook.
- `.github/workflows/deploy.yml` — staging on merge to `main`, production on tag, rollback on dispatch.

## Interfaces

```bash
pnpm build:server                  # -> apps/server/dist/server.mjs
infra/deploy.sh staging            # build/pull, tag, up
infra/deploy.sh production <tag>   # deploy a tagged release
infra/deploy.sh rollback <tag>     # re-pull the previous image
```

## Data

No schema change. The expand-and-contract migration check already runs in CI (`pnpm migrations:check`).

## Test cases

1. `pnpm build:server` produces a bundle that imports and exits cleanly.
2. `terraform fmt -check` passes.
3. The migration check fails a destructive migration (already proven in CI).

## Out of scope

The actual `terraform apply`, restore drill execution and deploy to staging — these need the AWS account, domain and GitHub secrets (NEEDS N7).
