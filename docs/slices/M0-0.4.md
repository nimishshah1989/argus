# M0-0.4 — Auth

## Goal

A user can sign in from a phone or a shared phone, get a 30-day sliding bearer session, read their own profile, change their password and sign out. The tenant comes from the host; the session token decides the tenant after login. All of it is behind the RLS schema from M0-0.3.

## Files

- `packages/shared/package.json`, `packages/shared/src/auth.ts`, `packages/shared/src/error.ts` — request schemas and the error envelope.
- `apps/server/package.json`, `src/config.ts`, `src/db.ts`, `src/tenant.ts`, `src/session.ts`, `src/errors.ts`, `src/auth.ts`, `src/app.ts`, `src/index.ts`.
- `apps/server/test/auth.test.ts` — Testcontainers Postgres; login, me, logout, password, shared acting person, brand, cross-tenant, sliding.
- `docs/slices/M0-0.4.md` — this plan.

## Interfaces

```
GET    /api/v1/health
GET    /api/v1/brand                       (public, rate-limited; host decides tenant)
POST   /api/v1/auth/login                  { username, password, device?, actingPersonId? }
GET    /api/v1/auth/me                     (Bearer)
POST   /api/v1/auth/logout                 (Bearer)
POST   /api/v1/auth/password               { old, password }   (Bearer)
```

Error envelope: `{ error: { code, message, field? } }` with codes `unauthenticated`, `validation`, `not_found`, `rate_limited`, `internal`.

## Data

- `tenant_by_slug(host subdomain)` → tenant; `auth_lookup(token_hash)` → tenant/login/person/role/shared/acting/expiry.
- `login` (Argon2id), `session` (token SHA-256, 30-day sliding), `person` (name/title for the acting person).

## Rules

- One auth mechanism: an opaque bearer token for every client, hashed at rest.
- Personal login records its person; a shared login requires an acting person from the plant’s active people.
- 30-day sliding expiry on every authenticated request.
- Wrong password and unknown username return the same `unauthenticated`; no user enumeration.
- Tenant from host before login; from the session token after login.

## Test cases

1. `/brand` returns the right company per host; unknown or bare host is `not_found`.
2. Personal login returns a token and user; `/me` returns the same user.
3. Wrong password and unknown username both return `unauthenticated`.
4. Shared login without an acting person is `validation`; with one it sets `acting_person_id`.
5. Logout revokes the session; `/me` then returns `unauthenticated`.
6. Change password: wrong old password fails; correct one works, revokes the other sessions, and the new password signs in.
7. `/me` twice slides the expiry forward.
8. A token from tenant A works even if the host header says tenant B (the token is authoritative).
9. A password under 8 characters is `validation`.

## Out of scope

Registration, password reset, device list/revoke UI (M2), rate-limit tuning, audit of logins. Tenant creation is manual.
