# M0-0.5 — Settings and configuration

## Goal

A list edited in Settings is returned by `/config` with a new fingerprint. Admins and heads edit lists, features and translations; every authenticated client reads the full per-tenant config.

## Files

- `packages/shared/src/config.ts` — list, settings and translation schemas; the list vocabulary.
- `apps/server/src/config.ts` — assemble the per-tenant config and compute its fingerprint.
- `apps/server/src/settings.ts` — settings, lists, translations routes.
- `apps/server/src/app.ts` — register the settings routes.
- `apps/server/test/settings.test.ts` — Testcontainers; fingerprint, list edit, permissions, translations.
- `packages/db/migrations/0001_schema_v1.sql` — add `tenant_info(id)` (the config needs language/time zone, which `app_user` cannot read from `tenant` directly).
- `docs/slices/M0-0.5.md` — this plan.

## Interfaces

```
GET   /api/v1/config?fp=            -> { fp, features, language, timeZone, lists, segments, groups, machines, people, shifts } | { same:true, fp }
GET   /api/v1/settings              -> [{ key, value }]
PUT   /api/v1/settings/:key         { value }
GET   /api/v1/lists/:list           -> items
PUT   /api/v1/lists/:list/:code     upsert { label, labelGu?, labelHi?, sort?, active?, isVendor?, pausesSla?, tag? }
DELETE /api/v1/lists/:list/:id
GET   /api/v1/translations/missing  -> items without label_gu
PUT   /api/v1/translations/:id      { labelGu?, labelHi? }
```

Writes require role `admin` or `head`; reads require any authenticated session.

## Data

`list_item`, `setting`, `segment`, `machine_group`, `machine`, `person`, `shift`, and `tenant_info(id)`.

## Rules

- Fingerprint is the first 12 hex of SHA-256 over the canonical config JSON, excluding `fp`.
- `?fp=` returns `{ same:true, fp }` when nothing changed.
- A list name is validated against the fixed vocabulary; unknown list is `not_found`.
- Missing translations are `list_item` rows with no `label_gu`.

## Test cases

1. `/config` returns features, lists and a fingerprint; the wait-reason list is present.
2. `?fp=<old>` returns `same:true`; after a list edit the fingerprint changes.
3. A technician cannot write; `admin` can.
4. `PUT /settings/features` updates `/config` features.
5. Missing translations are listed; setting `labelGu` removes the item.
6. Unauthenticated `/config` is `unauthenticated`.

## Out of scope

People/machine/shift write screens (config reads them already), the React Settings UI (next sub-slice, with the web scaffold), registration and tenant creation.
