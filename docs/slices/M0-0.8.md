# M0-0.8 — Walking skeleton

## Goal

A user signs in, raises a stopped ticket on the floor screen, and sees it on the desk Open list. This is the first end-to-end vertical slice and runs locally without AWS.

## Files

- `packages/domain/package.json`, `src/refs.ts` — pure ticket-reference formatting.
- `apps/server/src/tickets.ts` — minimal `POST /tickets` (raise) and `GET /state` (open list), to be replaced by the full state machine in M1a.
- `packages/shared/src/ticket.ts` — raise request schema.
- `apps/server/test/tickets.test.ts` — raise, duplicate, open list, permissions.
- `apps/web/` — Vite + React scaffold: login, floor (report), desk (open list).
- `docs/slices/M0-0.8.md` — this plan.

## Interfaces

```
POST /api/v1/tickets   { machineId, problem, kind?, reportedByPersonId?, startNow? } -> { ticket }
GET  /api/v1/state     -> { open: [tickets], now }
```

## Rules

- The `ref` is `BD-<n>` from `ref_counter`, formatted in `packages/domain` (pure, tested).
- A second open non-general ticket on the same machine returns `conflict` with the existing ticket.
- The full state machine, figures and permissions matrix land in M1a; this slice is deliberately minimal.

## Test cases

1. Raise a stopped ticket returns a `BD-` ref and appears in `/state`.
2. A second raise on the same machine returns `conflict`.
3. Unauthenticated raise is `unauthenticated`.
4. `refs.nextRef` formats `BD-0150` correctly.

## Out of scope

The state machine, figures, pause/resume/transfer, offline, PDFs, and the full ticket UI (M1a/M1b).
