# M1a-5 — Floor and desk faces

## Goal

The real faces on top of the M1a-4 tickets API: an operator raises a ticket on the
floor in three taps and sees the confirmation; a technician sees the Open board, opens a
ticket's detail and drives it through its actions. One static React PWA (`apps/web`).

## Dependencies and decisions

- **Design system**: introduce Tailwind CSS with a small token set (status colours per
  `SPEC.md` §7 — stopped red, in progress blue, support/follow-up amber, transferred
  violet, waiting orange, running neutral) and TanStack Query (30s refetch). shadcn/ui is
  deferred until a component genuinely needs it (floor/desk are forms + lists). Both are
  pre-approved in `BUILD-PROTOCOL.md` §4/§8.
- **i18n**: English copy only for M1a-5; the `packages/shared/i18n` extraction and Gujarati
  strings stay in M1b (SPEC 1.11). No string is machine-translated.
- **`GET /tickets` list is NOT part of this slice** (it was deferred from M1a-4). The Open
  board derives from `GET /state`; Mine/Team/My-complaints need the list endpoint and are a
  follow-up (M1a-5c).

## Sub-slices (one PR each, merged on green)

### M1a-5a — Floor face (SPEC 1.3)

- Machine search + segment groups from `/config`; situation (`kind`: stopped / support /
  work request); problem text + quick-problem chips; work-request form (location + work
  type) when `kind=general`; sent confirmation showing the `ref`.
- Files: `apps/web/src/screens/Floor.tsx` (rewrite), `apps/web/src/screens/floor/*` (split
  if the screen exceeds 300 lines).

### M1a-5b — Desk face (SPEC 1.4)

- Open board: counts strip and three lists (Breakdowns/`stopped`, Tasks/`general`,
  Work/`support`) from `/state`; "team now" strip (lead persons).
- Ticket card with state-dependent actions (start, pause/resume, transfer, update,
  machine-running/stopped, close, cancel) calling the M1a-4 command endpoints.
- Ticket detail sheet: facts, timeline, people and figures from `/tickets/{id}`.
- Files: `apps/web/src/screens/Desk.tsx` (rewrite), `apps/web/src/screens/TicketDetail.tsx`
  (new), `apps/web/src/components/*` (TicketCard, ActionBar, Figures).

## Shared scaffolding (first commit of M1a-5a)

`apps/web/package.json` (tailwindcss + @tanstack/react-query), `apps/web/vite.config.ts`,
`apps/web/index.html`, `apps/web/src/main.tsx` (QueryClientProvider),
`apps/web/src/style.css` → Tailwind directives + tokens, `apps/web/src/api.ts` (typed
`raise`/`command`/`state`/`detail` helpers + `Idempotency-Key` per request),
`apps/web/src/App.tsx` (routes `/floor`, `/desk`, `/desk/:id`).

## Write scopes (next session, disjoint)

- **scaffold worker** — the shared files above (package.json, vite.config, index.html,
  main.tsx, style.css/tokens, api.ts, App.tsx). Lands before the others branch off.
- **floor worker** — `apps/web/src/screens/Floor.tsx` + `screens/floor/*`.
- **desk worker** — `apps/web/src/screens/Desk.tsx`, `screens/TicketDetail.tsx`,
  `components/*`.
- **reviewer** — read-only, fresh context, reviews each PR against this plan + QUALITY-BAR.

No two workers touch one file. `apps/server` and `packages/*` are not modified (the M1a-4
API already serves every command the faces call).

## Test cases

1. Floor raise (Playwright): pick a machine, type a problem, send → confirmation shows a
   `BD-` ref; the ticket appears in the desk Open list.
2. Floor work request: `kind=general` asks for location + work type (no machine).
3. Desk Open: three lists split by kind; counts strip matches; "team now" shows lead names.
4. Ticket detail: facts/timeline/people/figures render from `/tickets/{id}`.
5. Drive one ticket (Playwright): start → update → pause → resume → join → leave →
   transfer → pick up → machine-running → machine-stopped → close with report; each action
   is a POST with a fresh `Idempotency-Key`; the UI reflects the new status/figures.
6. Permission: operator sees no work actions on the desk (server 403 paths already tested).
