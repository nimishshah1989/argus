# M2-2.2 — SLA policies and delayed timers

## Scope and decision

Add per-tenant SLA policies for ticket severities and real delayed acknowledge/restore timers.
Every ticket command recomputes and re-arms its timers from the effective ticket fields and complete
ordered event history. The acknowledge clock stops at the first acknowledge/start/pickup. Restore
stops at close, or first machine-running for a stopped ticket. Only waits whose event-snapshotted
`pausesSla=true` pause restore; transfers never pause it. Business-hours mode is off by default and,
when enabled, counts only the union of declared shift windows.

**Out of scope:** the `acknowledge` command, escalation rules/roster/notifications, pause-overrun
and handback timers, failed-jobs UI and timer-lag alarm. These are M2-2.3–2.5.

## Public contract

### DTOs

```ts
interface SlaPolicy {
  id: string;
  severity: 'S1' | 'S2' | 'S3' | 'S4';
  ackMinutes: number; // positive integer
  restoreMinutes: number; // positive integer
  businessHoursOnly: boolean;
}

type TimerKind = 'ack' | 'restore';
type TimerState = 'running' | 'paused' | 'stopped';

interface SlaTimer {
  id: string;
  state: TimerState;
  breached: boolean;
  dueAt: string | null; // null only for an unbreached paused timer
  pausedAt: string | null; // only an explicit pauses_sla pause
  stoppedAt: string | null;
  remainingMinutes: number; // signed snapshot; away-from-zero rounding
}
```

Ticket projections add `slaPolicyId: string | null` and
`sla: {ack: SlaTimer | null; restore: SlaTimer | null} | null`. The server emits both timers when a
policy exists. `remainingMinutes` is computed at the projection boundary, never stored. `firedAt`,
queue ids and revisions stay internal; visible breach state never depends on a worker. Domain and
persistence retain stop reasons for audit; the browser uses neutral text plus existing ticket status.

`GET /api/v1/config` adds `slaPolicies: SlaPolicy[]`. An empty array is valid initial configuration:
there are **no default targets**. The first valid four-policy save creates stable rows and binds live
tickets. Before then, tickets expose `sla: null`; zero-minute timers are never invented. The browser
shows blank targets only after real config has loaded, never a fabricated default.

`PUT /api/v1/settings/sla-policies` accepts all four policies atomically:
`{policies: Array<Pick<SlaPolicy, 'severity' | 'ackMinutes' | 'restoreMinutes' | 'businessHoursOnly'>>}`.
Every severity appears exactly once and minutes are positive integers. Admin/head only. Updating
policies re-arms affected tickets in the same tenant transaction and changes the fingerprint.
Existing `pause_max_minutes` and `handback_minutes` columns remain for their owning slices.

Wait reasons use the existing `PUT /api/v1/lists/wait_reason/:code`. Its `pausesSla` flag affects
**future pauses only**; existing pauses keep their snapshot. Help copy states exactly that. The web
sends the complete current list item so unrelated labels/flags are preserved.

## Domain projection and state transitions

`packages/domain/src/sla.ts` exports pure `projectSlaTimers(input)` returning both timers;
`business-hours.ts` exports calendar calculations. No I/O, global clock, random ids or input mutation.

Input contains the effective ticket fields, ordered events, matching policy, shift windows and time
zone. Existing timer rows are merged by the server afterward; the pure function does not know
`firedAt` or queue revisions. Every pause event must carry historical `pausesSla`; missing values
raise `missing_pause_flag` rather than silently becoming false.

Output for each clock: `id`, `state`, `breached`, `dueAt`, `pausedAt`, `stoppedAt`,
`remainingMinutes`, plus internal stop reason. `remainingMinutes` is signed and rounded away from
zero. A running timer breaches at exact dueAt; a terminal event at exact dueAt is on time. A stopped
timer may also be late. During the server-side merge with the existing timer row,
`requiresDueProcessing === (breached && firedAt === null && stopReason !== 'cancelled')`, so late
stopped timers are included while cancelled timers are excluded.

| Event/condition                            | Ack                                                   | Restore                                               |
| ------------------------------------------ | ----------------------------------------------------- | ----------------------------------------------------- |
| raise at effective reportedAt              | running                                               | running                                               |
| first acknowledge/start/pickup; self-start | stopped for earliest reason                           | no effect                                             |
| `pausesSla=true` pause                     | normally stopped already                              | running → paused at event; due recomputed on resume   |
| `pausesSla=false` pause                    | no effect                                             | no effect                                             |
| transfer/handover                          | no effect                                             | never paused                                          |
| first running while kind=stopped           | no effect                                             | stopped/machine_running; later stopped never restarts |
| close                                      | stopped/closed if not already stopped                 | stopped/closed if not already stopped by running      |
| cancel                                     | stopped/cancelled; no active job                      | stopped/cancelled; no active job                      |
| restore after cancel                       | recompute excluding cancelled gap                     | recompute running/paused excluding cancelled gap      |
| irrelevant correction                      | recompute fields only; firedAt unchanged              | same                                                  |
| corrected reportedAt/severity              | recompute unfired timers from corrected origin/policy | same                                                  |

Late stop behavior: a start/running/close after the deadline is `stopped + breached`, and the missed
timer is still eligible for one due-processing write. `firedAt` records processing time, not the
deadline. A terminal tie is on time. An already-fired logical timer never fires again automatically.

Correction semantics: `startedAt` corrects first-response start, not latest pickup; fold edit events
in sequence. `closedAt` corrects effective close. Kind controls whether running terminates restore.
Severity selects the newly matching policy. Reporting overrides never change SLA arithmetic.
Invalid effective timelines raise `SlaInputError` rather than clamping them into plausible values.
Corrected report/start/close times must be at or before the correction/projection time, at or after
report time, and in start/close order; the command and pure projection both reject violations.

## Business calendar

A `ShiftWindow` has `{code, startMinute, endMinute, crossesMidnight}`. Windows recur daily and are
half-open `[start,end)`: start is inclusive, end exclusive. Overnight windows end next day. Adjacent
and overlapping intervals are merged in absolute time so minutes never double-count; zero-length
windows are invalid. The existing 18:29/18:30 overlap is one continuous eligible interval for SLA.

`businessMinutesBetween(from,to,calendar)` and `addBusinessMinutes(from,minutes,calendar)` use the
tenant IANA zone and explicit local-midnight offsets (including DST transitions), not fixed offsets.
The algorithm steps to window starts/ends rather than iterating minutes. `businessHoursOnly=false`
is 24×7 and needs no calendar. Empty/invalid shift config is `invalid_calendar`, never fallback.
Off-hours are excluded only when enabled and are never `pausedAt`.

24×7 pauses shift due by exact wall-clock paused time. Business-mode pauses shift only by eligible
working minutes inside the pause. A pause outside working hours leaves remaining work unchanged
until the next eligible window, while `pausedAt` still records the explicit pause event. Cancel gaps
are excluded before business-hours arithmetic, preventing double exclusion.

## Migration 0007

- `sla_policy`: `id`, `tenant_id`, `severity`, `ack_minutes`, `restore_minutes`,
  `pause_max_minutes`, `handback_minutes`, `business_hours_only`, timestamps. Checks: severity S1–S4,
  positive ack/restore minutes, and positive nullable pause/handback minutes reserved for 2.3/2.4.
  `UNIQUE(tenant_id, severity)` and `UNIQUE(tenant_id, id)`; forced RLS and standard grants.
- `sla_timer`: `id`, `tenant_id`, `ticket_id`, `kind`, `due_at`, `paused_at`, `fired_at`,
  `stopped_at`, `stop_reason`, `state`, `job_id`, `revision`, timestamps. Checks: kind ack/restore,
  state running/paused/stopped, revision > 0, pausedAt only for paused, stoppedAt/stopReason only for
  stopped. Ack stop reasons are `acknowledged|started|closed|cancelled`; restore reasons are
  `machine_running|closed|cancelled`. `UNIQUE(tenant_id, ticket_id, kind)` and partial index
  `(tenant_id, due_at)` for non-stopped unfired timers; forced RLS and composite FK to
  `ticket(tenant_id,id)`. `job_id` is diagnostic only, with no FK because queue jobs expire.
- `ticket.sla_policy_id` stays nullable and gains a composite FK to `sla_policy(tenant_id,id)`.
  A cross-tenant policy id is rejected. No default targets are seeded; new tenants configure four
  policies before ticket timers exist.
- A narrow `app_router` `SECURITY DEFINER` `tenants_with_sla_policies()` returns only tenant ids
  with policies for the daily consistency job. Owner is `app_router`, search_path is pinned, and only
  `app_user` may execute it. No ticket fields cross tenant boundaries.
- Legacy pause events are backfilled with `pausesSla` from the current matching wait_reason as an
  enablement decision after a full backup. Backup → resolve every legacy reason → additive backfill →
  abort migration if any remain unresolved; missing values never default to false. Present null,
  string or other non-boolean values also abort rather than escaping validation. Importer and new API
  writes persist the snapshot explicitly. No severity, event timestamps or figures are changed.
- Existing live tickets bind on the first valid policy PUT. Ordinary closed tickets receive completed
  projections for reporting; backfilled `raised_channel='backfill'` rows are excluded from timers.
  Imported active/closed rows get the same treatment, and importer assigns policy by severity.
  `packages/db/test/sla-migration.test.ts` asserts all table/check/FK shapes, including the reserved
  `pause_max_minutes` and `handback_minutes` columns.

## Delayed jobs

Pin `pg-boss@12.38.2` and record ADR 0005. `packages/db/src/install-jobs.ts` exposes
`installJobSchema(pool)`, which starts/stops the pinned installer with `migrate:true` and applies grants.
The tracked production `scripts/migrate.ts` runs app SQL → pg-boss installer → app start with a
privileged URL and ensures the `app_api` login exists. Migration + ledger writes are atomic and the
session advisory lock releases on disconnect. Unledgered 0006/0007 schemas are never adopted. A
legacy upgrade requires an explicit `MIGRATION_ADOPT_THROUGH` naming the proven last migration from
0001–0005; artifact probes only sanity-check that declaration. Every run enforces `app_api INHERIT
NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOREPLICATION`, and `withTenant` fails closed if
`app_api` can bypass RLS. `apps/server/test/harness.ts` invokes the runner once per disposable
container. Production app and test workers use `migrate:false`. Queue tables live in the `pgboss`
schema, exempt from tenant-table RLS. Runtime grants are concrete:
`GRANT USAGE ON SCHEMA pgboss TO app_user`; `GRANT SELECT,INSERT,UPDATE,DELETE ON ALL TABLES IN SCHEMA
pgboss TO app_user`; `GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA pgboss TO app_user`; sequence/default
privileges where present. The isolation suite tests this exact inherited `app_api` path.

`packages/db/test/isolation.test.ts` explicitly adds `sla_policy` and `sla_timer`;
`packages/db/test/seed.sql` adds two-tenant policy/timer rows and queue-grant assertions. Tests cover
forced RLS, unset tenant, cross-tenant FK rejection, router output/grants and real inherited `app_api`
queue access.

`apps/server/src/jobs/`:

- `adapter.ts`: exposes `{executeSql}` over the current `PoolClient`.
- `index.ts`: startup/shutdown, queue creation, `ROLE=all|api|worker`, error handler.
- `sla-timer.ts`: ARM/DUE handler and `rearmTicket` helpers.
- `sla-consistency.ts`: startup/daily reconciliation over policy tenant ids.

Protocol:

- ARM only `running + unbreached + dueAt non-null + fired_at IS NULL`, with
  `upsert({name:'sla.timer', data:{tenantId,ticketId,kind,revision}, options:{singletonKey:`${tenantId}:${ticketId}:${kind}`,startAfter:dueAt,db}})`.
- PROCESS DUE for any non-cancel breached unfired timer (including paused+breached and late stopped),
  using an atomic conditional update guarded by id, revision, current dueAt and `fired_at IS NULL`.
  Two workers cannot both mark the same timer fired. `fired_at` is processing time and never cleared.
- Cancellation uses `findJobs('sla.timer', {key: singletonKey, db})`, filters to created/retry/active
  jobs at the previous revision, then calls `cancel('sla.timer', ids, {db})`. New work arms at the
  incremented revision; stale or duplicate same-revision work is a no-op.
- Standard queue policy; upsert supplies deduplication for not-yet-active jobs. Rollback of ticket,
  timer and queue writes is tested. Tests invoke handlers directly with injected now/queue access,
  never sleep for a timer. A real pinned-package `TestClock` integration proves deferred ARM fires,
  past-due (including paused+breached) fires immediately, active stale jobs no-op, retries cannot
  double-fire, and queue+ticket rollback. The same clock is injected into SLA code; TestClock does
  not change SQL `now()` or app `new Date()`.

`ROLE=all` starts jobs normally; `ROLE=api` disables workers; `ROLE=worker` starts only jobs.
`sla.consistency` is scheduled at `0 4 * * *` with `{key:'all',tz:'UTC',missed:'once'}`, plus an
immediate boot run and a per-tenant post-import run. Repeated runs are no-ops. Startup/daily
consistency re-arms missing/stale timers without touching other tenants.

## Ticket integration

`apps/server/src/ticket/sla.ts` locks the ticket before loading policy, ticket and event context,
then calls the domain projection, upserts timer rows and performs ARM/cancel/DUE work while holding
that lock in the same transaction. Policy/consistency reconciliation therefore cannot overwrite a
newer command with a stale projection. Policy saves and machine-criticality updates take the same
tenant BD ref-counter lock used by raise/import before reading or writing SLA state, so a concurrent
first policy save cannot miss a raise or leave it without persisted timers/jobs. Every multi-ticket
lock/reconciliation traversal uses `ORDER BY id`, matching daily consistency and preventing opposing
lock-order cycles. Raise validates machine state only after taking that same BD lock. Raise assigns
`ticket.sla_policy_id` and both timers. Start/pickup completes ack; close/first running completes
restore; cancel stops both; pause/resume updates restore only for snapshotted pauses; correct/restore
reprojects; severity/policy changes update `ticket.sla_policy_id` and re-arm. Importer follows the
same policy assignment/projection rules instead of bypassing them.

`apps/server/src/ticket-sql.ts` persists `sla_policy_id`. `apps/server/src/sla-projection.ts`
batch-loads timers for ticket ids and maps public DTOs; it is used by `/state` open+needReport,
`/tickets`, `/tickets/:id`, raise and every command response without per-card queries.
`apps/server/src/config.ts` serves policies. `apps/server/src/settings.ts` updates policies before
the generic `/settings/:key` route and writes `audit_log`. `apps/server/src/index.ts` starts jobs in
production; `apps/server/src/app.ts` closes jobs during app shutdown in tests.

`packages/shared/src/sla.ts` is the Zod/type source for policy PUT, config policy, timer and response
schemas used by server and web. Success is `{ok:true}`; validation errors are 422, forbidden 403,
unknown ticket/policy 404. Tests cover every admin/head/forbidden role and malformed payload.

## Given / When / Then tests

1. Ack due = report + target; start, pickup and self-start stop it; acknowledge/start earliest wins.
2. Unstarted ticket breaches at exact due and delayed processing records it exactly once.
3. Restore stops at close or first running, including waiting; later stopped never restarts it.
4. `pauses_sla=true` pause moves restore due and sets paused; non-SLA pause and transfer do not.
5. A paused-before-deadline timer does not breach from wall-clock aging; a paused-after-deadline
   timer is processed immediately. Late start/running/close records one missed timer.
6. `correct` moves reportedAt/first-start/close appropriately; irrelevant edits preserve firedAt;
   restore excludes cancelled gap and revives only previously unfinished clocks.
7. Business hours handles overnight/adjacent/overlapping windows, exact boundaries and DST where
   applicable; empty/invalid config errors. Add a worked pause/resume example outside hours.
8. Policy update affects only matching severity/tenant. First valid PUT binds live ordinary tickets;
   backfilled rows are excluded. New tenant has empty config and no timers until configured.
9. Importer active/closed rows follow the same rules and cannot create a cross-tenant policy link.
10. Concurrent commands yield one live job per ticket/kind; conditional fire wins once; stale revision
    and replay are no-ops. Ticket+queue rollback works.
11. Daily consistency creates missing timers and re-dates stale ones without cross-tenant writes.
12. UI policy roundtrip, loading failure recovery, role gate, offline snapshots, existing action
    lifecycle and correction/cancel/restore are proven on desktop+phone. No Acknowledge/escalation UI.

## Risk, review and size

R3: new tenant tables, a migration and cross-tenant job runner. Requires plan, architecture,
schema, code and security reviews before merge; a human security sign-off is still required before
production cutover. Timer semantics are frozen by this plan; workers must not invent pause states,
notification behavior or new SLA targets.

`size:large`: the slice spans domain/calendar logic, migration, job infrastructure, ticket/API
integration and the Settings/ticket UI with real fake-clock, database and browser coverage. No
unrelated refactors are allowed; an implementation/review split may land sequentially without
claiming partial timer behavior.
