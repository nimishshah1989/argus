# M0-0.3 — Schema v1 with RLS and app_router

## Goal

A new database can be created from migrations and holds tenant data so that two tenants can never read each other’s rows through the application role. One narrow `app_router` role resolves a host to a tenant and a session token to a tenant/login before `app.tenant_id` is set.

## Files

- `packages/db/package.json` — `pg` dependency, private package.
- `packages/db/migrations/0001_schema_v1.sql` — all v1 tables, indexes, RLS policies, roles, grants, `tenant_by_slug`, `auth_lookup`.
- `packages/db/test/seed.sql` — one row per tenant in every tenant table, fixed ids for cross-references.
- `packages/db/test/isolation.test.ts` — Testcontainers Postgres 16; migration; two tenants; RLS, policy, function and role assertions.
- `packages/db/src/tenant.ts` — `withTenant()` transaction wrapper; throws `MissingTenantError` before a query when the tenant is missing.
- `packages/db/test/tenant.test.ts` — the wrapper sets the tenant and throws without one.
- `docs/slices/M0-0.3.md` — this plan.

## Interfaces

```sql
tenant_by_slug(p_slug text)
  returns table(id uuid, slug text, name text, language text, time_zone text)

auth_lookup(p_token_hash text)
  returns table(tenant_id uuid, login_id uuid, person_id uuid, role text,
                shared boolean, acting_person_id uuid, expires_at timestamptz)
```

Both are `SECURITY DEFINER`, owned by `app_router`, executable by `app_user`, revoked from `PUBLIC`. `app_user` has no `BYPASSRLS`; `app_router` has `BYPASSRLS` but only `SELECT` on `tenant`, `person`, `login`, `session`.

## Data

v1 tables: `tenant`, `person`, `login`, `session`, `platform_access`, `segment`, `machine_group`, `machine`, `machine_move`, `list_item`, `shift`, `setting`, `glossary_term`, `ticket`, `ticket_event`, `crew_member`, `work_segment`, `breakdown_report`, `file`, `push_subscription`, `audit_log`, `import_batch`, `import_row`, `ref_counter`, `command_idempotency`.

Every table except `tenant` has `tenant_id`, `ENABLE ROW LEVEL SECURITY`, `FORCE ROW LEVEL SECURITY`, and one policy using `current_setting('app.tenant_id', true)::uuid`. `tenant` is resolved only through `tenant_by_slug`. No `plant` table and no settings scopes in v1 (M5).

## Test cases

1. Every tenant table has RLS enabled and forced, and exactly one policy.
2. `app_user` cannot bypass RLS; `app_router` can.
3. Seeded as tenant A, every tenant table returns exactly 1 row; tenant B returns 1; the other tenant’s rows are absent.
4. With `app.tenant_id` unset, every tenant table returns 0 rows.
5. `auth_lookup` with tenant B’s token returns tenant B even while `app.tenant_id` is tenant A.
6. `tenant_by_slug('cosmos')` returns the Cosmos tenant.
7. A token with no session, an expired session or a revoked session returns no row (seed variants).
8. `ticket_event` enforces unique `(ticket_id, seq)` and idempotency key; `command_idempotency` enforces unique `(tenant_id, key)`.
9. A cross-tenant parent reference is rejected by the composite `(tenant_id, id)` foreign key.
10. `withTenant()` throws before a query when the tenant is missing.

## Out of scope

Drizzle query schema, API handlers, `seed:cosmos`, business queries, M2/M3/M4 tables, UUID v7 generation. These follow in M0-0.4 onward.
