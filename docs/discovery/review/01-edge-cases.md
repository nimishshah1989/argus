# Review 01 — Domain correctness and edge cases

Reviewer lens: domain correctness, state machine, derived figures, time, identity, migration, permissions, SLA semantics. Read: SPEC.md (full), Domain model & API tab (exported as DOMAIN.md), Parity checklist tab (exported as PARITY.md), bhavin-v3/INVENTORY.md, live-config-2026-11-09.json, glossary-2026-11-09.json, and app.js / ref.js where a rule needed checking (line numbers below are app.js unless stated).

## Verdict

1. The spec is strong on *what* v3 does and weak on *how the interval model reproduces v3's stored numbers*: three definitions (hands-on, admin corrections, restore) cannot be implemented as written without producing numbers that differ from Bhavin's, which defeats the parity gate for 1.10.
2. Identity is under-specified where it matters most: the floor's reporters are free text today, the spec forbids free text, and gives no fallback or import rule, so both the floor and the migration stall on day one.
3. Several permission cells tighten v3 while the parity row says Keep (transfer; close on a shared phone); the M2 handback cell references a `cell` attribute that no table has.
4. Concurrency, offline replay and cross-tenant background work (SLA sweeper, WhatsApp routing, session lookup) are each described in one sentence that an agent will implement wrongly: no row lock, no idempotency key, no router role.
5. Nothing here needs a redesign. About 30 clarifications, most of them one paragraph, make the Domain tab buildable; the three Blockers must land before epic 1.1 starts.
