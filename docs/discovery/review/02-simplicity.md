# Review 02 — Simplicity and proportion

Reviewer lens: is the system more complex than its situation needs? Situation: one plant, ~190 machines, ~15 maintenance staff, ~250 tickets a month, a non-technical solo founder plus one vibe-coding partner, built by Claude Code sessions. Read: SPEC.md (all 13 sections), the Domain model & API tab and the Parity checklist tab (exported from the shared doc), and INVENTORY.md §1–4 plus §9, §12, §14, §15 for what the existing app actually is (a 2,045-line static JS client talking to one Cloudflare Worker with 25 endpoints).

## Verdict

1. **Yes, it is more complex than required — in shape, not in substance.** Postgres, an event log, a job queue, server-rendered PDFs and tenant_id-everywhere are the right bones. The over-build is around them: three deployables plus eight packages plus Turborepo for 15 users; Next.js for an offline PWA that is static today; four copies of every ticket's time figures; a five-scope settings cascade for one plant; trilingual UI strings before a second plant exists.
2. **It is under-built exactly where a live pilot bites:** no deploy rollback, a restore drill that is "documented" rather than run, no sanctioned way to fix bad data (CLAUDE.md rule 11 forbids sessions touching production, and nothing replaces them), and no deploy window for a plant that runs 08:00–05:00.
3. **Milestone order is right; the grain is wrong.** M0 ends with no screen a technician can use; M1 is the entire v3 app as one epic; M4 is two or three milestones. And the "parallel run" is not parallel: the spec says Cosmos uses ours only for a week (§12, §13), that Cosmos switches over after M2 (§4), and tells the import-timing story two ways. That week is a soft cutover and must be planned as one.
4. **Stack is mostly boring.** The two sharp edges for an agent-driven build: Next.js App Router (fast-moving; the spec itself says "verify the service-worker approach at build time") and RLS via Drizzle with `SET LOCAL` per request, the one failure mode that produces silent empty lists rather than errors.
5. **Hidden operational load the spec does not name:** WhatsApp's 24-hour window and per-language template approvals, Chromium's fonts and memory on a shared box, and the fact that any deploy or RDS maintenance must land between 05:00 and 08:00 IST.
