# Research: AI brain and knowledge base (28 Oct 2026)

## Key conclusions
1. Most incumbent "AI" is now commodity: voice-to-WO, manual Q&A, problem-code suggestion, similar past orders, duplicate detection, NL reporting, PM drafts from manuals, photo-to-asset. Deep AI (Tractian, Augury, Senseye, Aspen Mtell) rides on sensors.
2. Our moat = Gujarati/Hindi WhatsApp voice → verified, coded failure history for Indian CNC makes/controllers; every confirmation is a label.
3. Retrieval-first + closed label sets beat LLM-only: zero-shot GPT-3.5 F1 0.46 vs fine-tuned 0.80 on ISO 14224 failure modes (arXiv 2309.08181); retrieval beat LLM-only for fault-code selection (PHM 2025); rewording cuts accuracy 5-20% (FailureSensorIQ, arXiv 2506.03278).
4. ASR by benchmark: Voice of India (Apr 2026) Gujarati OI-WER Sarvam Audio 12.8, Saarika 2.5 14.0, Gemini 3 Pro 15.8, IndicConformer 18.0, GPT-4o Transcribe 98.2; Hindi Sarvam 5.0. No maintenance-domain Indian ASR benchmark → build our own test set.
5. OEM manuals: Fanuc "No part of this manual may be reproduced in any form"; India has no TDM exception (DPIIT proposal Dec 2025 not law; ANI v OpenAI pending) → tenant-scoped manuals only; global alarm index = number + own notes + pointer. Get IP counsel.

## Design
Layers: L0 global (classes, components, own codes, multilingual symptom lexicon, alarm index facts, PM templates) · L1 cross-tenant aggregates (k-anonymity, opt-in) · L2 tenant (assets, verified fix cases, tenant manuals/SOPs, people/skills, spares, slang; RLS incl. vectors) · L3 live (tickets, forecasts, roster, stock, production calendar).
Retrieval: FTS + pgvector + hard filters (tenant, class, make/model, controller); alarm codes exact match; store original transcript + normalised English + codes; typed edge tables (failure_mode→component, symptom→failure_mode, cause→action) with outcome weights.
Agents: 1 intake/triage · 2 failure coding (kNN then constrained LLM, abstain) · 3 diagnosis/fix-finder (cited cases, success rates; LLM explains only; safety rules) · 4 PM-plan generator (frontier, citations, approval) · 5 Why-Why/RCA · 6 report/briefing writer (no arithmetic) · 7 NL analytics (text-to-SQL on curated RLS views, SQL shown) · 8 onboarding/import mapping · 9 data quality · 10 planning (OR-Tools; LLM explains).
Build order: 1, 2, 9, 6 → 8, 7, 3 → 4, 5, 10.
Guardrails: no source no claim; codes selected not generated; numbers from SQL/stats only; calibrated self-consistency confidence + abstain; hard-coded safety rules; zero-retention LLM terms; voice notes = personal data (DPDP).
Evaluation: 300-500 voice notes (WER + entity accuracy, alarm exact match), 1,000 double-coded tickets (macro-F1, top-3, precision-coverage), 100 diagnosis replays (hit@3, citation faithfulness, robustness), 30 PM drafts; online acceptance/override/abstain rates; shadow → suggest → default per agent per tenant; regression suite on every prompt/model change.
Models: classical stats/OR for numbers and schedules; Sarvam-class ASR; small LLM for extraction/coding/briefings (fine-tune at ~2,000 labels); frontier for diagnosis synthesis, PM drafts, RCA, text-to-SQL, onboarding.
