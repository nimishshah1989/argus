## Non-negotiable architecture decisions

- No default SLA targets. Empty policy config is valid; first valid four-policy save binds tickets.
- Timer state is `running | paused | stopped`; breach is independent. Remaining minutes are derived,
  signed and rounded away from zero. `dueAt` is null only for paused+unbreached.
- Ack stops at first acknowledge/start/pickup. Restore stops at close or first machine-running for
  stopped tickets. A later machine stop does not restart restore.
- Only historical `pausesSla=true` pauses restore. Transfers never pause. Flag edits affect future pauses.
- Late stopped timers may be breached and receive one due-processing write. Cancelled tickets never
  process. `fired_at` is immutable and corrections never auto-refire.
- Business hours use the union of declared shift windows; empty config is an error when enabled.
- One shared pg-boss instance started at app startup. Never call `start()`, `createQueue()` or `stop()`
  inside a tenant transaction: createQueue commits and clears `app.tenant_id`.
- Reconciliation input is `{tenantId,ticketId,now,boss?}` and returns the matching policy id. The ticket
  locks before history is read. `startJobs` owns queue setup and ROLE handling; `onBossReady` injects
  the shared boss before workers. Policy saves/criticality use the raise/import BD-counter lock;
  multi-ticket reconciliation uses `ORDER BY id` to avoid opposing lock-order deadlocks.
- Import and criticality routes pass `options.boss`. Backfill rows do not expose SLA projections.
- Unledgered 0006/0007 is never adopted. Legacy adoption requires explicit 0001–0005 baseline input;
  `app_api` hardening starts immediately after the migration lock and runtime RLS fails closed.

## Learning rules required for every future build

1. **Infrastructure first, thin slice:** prove one real command through DB/API/queue before business features.
2. **Smaller vertical slices:** one user-visible flow per PR, with plan, tests, review and merge.
3. **Contract checks before code:** DTO mappings, column names, transaction boundaries, queue signatures,
   and state transitions are explicit and tested at boundaries.
4. **Real integration smoke early:** real Postgres and queue with injected clocks; no wall-clock sleeps.
5. **Reviews at thin-slice boundaries:** plan review before code, integration review after each slice,
   not after the whole feature.
6. **Deployment-safe migrations:** tracked ledger, atomic migration + record, advisory lock, artifact
   checks, and fresh/repeat/previous/crash-recovery tests.
7. **Parallelism only when independent:** disjoint worktrees/files, one E2E stack, no concurrent edits
   to shared transaction/startup code, dedicated fixtures.
8. **User-visible checkpoints:** preview each vertical slice instead of waiting for the milestone.
9. **Handoff early:** repo, slice plans, test output and task state are authoritative, not chat memory.
   Fresh orchestrator at ~50–70% context with a written handoff.
